Some computable problems have no eventually optimal program: every solution can be improved on almost all inputs. This separates being computable from possessing a best computational method and complicates the idea that a problem has an intrinsic complexity given by one optimal algorithm.

Statement

Fix a Blum complexity measure (\varphi,\Phi), where \varphi_i is the function computed by program i and \Phi_i(x) its complexity on input x. There is a total computable predicate g such that every program i computing g has a competitor j computing g with \Phi_j(x)<\Phi_i(x) for all but finitely many x. Consequently one cannot assign to every computable function the complexity of an optimal program computing it, where optimality would in particular forbid such an eventually strictly better competitor.

Proof 1: Apply speedup to rule out an optimum

Given a Blum complexity measure (\varphi,\Phi) and a total computable function F with two parameters, Blum's speedup theorem states that there exists a total computable predicate g (a boolean valued computable function) so that for every program i for g, there exists a program j for g so that for almost all x

F(x,\Phi_j(x))\leq\Phi_i(x).

Take F(x,y)=y+1. There is no optimal program computing this g, because every program has a program of lower complexity.

This also rules out the idea that there is a way to assign to arbitrary computable functions their computational complexity, meaning the assignment to any f of the complexity of an optimal program for f.

Level
Beyond undergraduate level
Level justification

Substituting F(x,y)=y+1 is elementary, but the full theorem is about arbitrary Blum complexity measures and indexed programs computing total predicates. Understanding the formal computability and axiomatic complexity framework requires more than a small extension of the ordinary undergraduate mathematical baseline.
