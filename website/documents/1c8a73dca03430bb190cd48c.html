Proof 1: Apply midpoint recursion to configurations — outline

The proof relies on an algorithm for STCON, the problem of determining whether there is a path between two vertices in a directed graph, which runs in {\displaystyle O\left((\log n)^{2}\right)} space for {\displaystyle n} vertices. The basic idea of the algorithm is to solve recursively a somewhat more general problem, testing the existence of a path from a vertex {\displaystyle s} to another vertex {\displaystyle t} that uses at most {\displaystyle k} edges, for a parameter {\displaystyle k} given as input. STCON is a special case of this problem where {\displaystyle k} is set large enough to impose no restriction on the paths (for instance, equal to the total number of vertices in the graph, or any larger value). To test for a {\displaystyle k}-edge path from {\displaystyle s} to {\displaystyle t}, a deterministic algorithm can iterate through all vertices {\displaystyle u}, and recursively search for paths of half the length from {\displaystyle s} to {\displaystyle u} and from {\displaystyle u} to {\displaystyle t}. This algorithm can be expressed in pseudocode (in Python syntax) as follows:

def stcon(s, t) -> bool:
    """Test whether a path of any length exists from s to t"""
    return k_edge_path(s, t, n)  # n is the number of vertices

def k_edge_path(s, t, k) -> bool:
    """Test whether a path of length at most k exists from s to t"""
    if k == 0:
        return s == t
    if k == 1:
        return s == t or (s, t) in edges
    for u in vertices:
        if k_edge_path(s, u, floor(k / 2)) and k_edge_path(u, t, ceil(k / 2)):
            return True
    return False

Because each recursive call halves the parameter {\displaystyle k}, the number of levels of recursion is {\displaystyle O(\log n)}. Each level requires {\displaystyle O(\log n)} bits of storage for its function arguments and local variables: {\displaystyle k} and the vertices {\displaystyle s}, {\displaystyle t}, and {\displaystyle u} require {\displaystyle O(\log n)} bits each. The total auxiliary space complexity is thus {\displaystyle O\left((\log n)^{2}\right)}. The input graph is considered to be represented in a separate read-only memory and does not contribute to this auxiliary space bound. Alternatively, it may be represented as an implicit graph. Although described above in the form of a program in a high-level language, the same algorithm may be implemented with the same asymptotic space bound on a Turing machine.

This algorithm can be applied to an implicit graph whose vertices represent the configurations of a nondeterministic Turing machine and its tape, running within a given space bound {\displaystyle f(n)}. The edges of this graph represent the nondeterministic transitions of the machine, {\displaystyle s} is set to the initial configuration of the machine, and {\displaystyle t} is set to a special vertex representing all accepting halting states. In this case, the algorithm returns true when the machine has a nondeterministic accepting path, and false otherwise. The number of configurations in this graph is {\displaystyle 2^{O(f(n))}}, from which it follows that applying the algorithm to this implicit graph uses space {\displaystyle O(f(n)^{2})}. Thus by deciding connectivity in a graph representing nondeterministic Turing machine configurations, one can decide membership in the language recognized by that machine, in space proportional to the square of the space used by the Turing machine.
