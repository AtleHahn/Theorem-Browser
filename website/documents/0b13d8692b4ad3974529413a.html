Statement

For an integer n\ge1, use deterministic Turing machines with n operational states, a separate Halt state, one starting state, a two-way unbounded tape over \{0,1\}, and a transition for each operational state and scanned symbol. Each transition writes a bit, moves one cell left or right, and enters a state (possibly Halt). The machine starts on an all-zero tape. Among machines that halt, \Sigma(n) is the largest number of ones left on the tape, and S(n) the largest number of transitions, including the halting transition. Define \operatorname{num}(n) as the largest number of consecutive ones a halting machine can output as a single unary block, and \operatorname{space}(n) as the largest number of tape cells read before halting, excluding a cell reached only by the final move. Then num is not Turing-computable.

Proof 1: Transfer through the state-rescaled comparison — outline

The function \operatorname{num}(n) can be shown to be uncomputable by proving, for example, that \operatorname{space}(n)<\operatorname{num}(3n+3): the source describes designing a (3n+3)-state Turing machine which simulates the n-state space champion, and then uses it to write at least \operatorname{space}(n) contiguous ones to the tape. The simulator and state accounting are not supplied; this description alone establishes neither the stated strict inequality nor its exact state bound.

Use the explicit external comparison \operatorname{space}(n)<\operatorname{num}(3n+3) and Radó’s theorem that \Sigma(n) eventually exceeds every total computable function. Every written one is on a visited cell, so \Sigma(n)\le\operatorname{space}(n). If num were computable, then f(n)=\operatorname{num}(3n+3) would be a total computable function exceeding \Sigma(n) for every n, contrary to Radó’s theorem.
