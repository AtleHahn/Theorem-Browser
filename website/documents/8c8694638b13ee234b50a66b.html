Statement

Fix a deterministic k-tape Turing machine M with k>1 and a positive integer m. Encode m consecutive symbols of each tape as one symbol in a larger alphabet. Given an encoded configuration with the current simulated state and each original head position within its block in finite control, a machine with the same number of tapes can simulate a full block of m transitions of M using at most six transitions of its own, returning an encoded configuration with the updated simulated state and within-block head positions.

Level
Within undergraduate level
Level justification

A multitape Turing machine is a finite transition rule on tapes and head positions. This single concrete computational model is a limited extension of finite algorithms; no complexity-class theory is required.

Proof 1: Read neighboring blocks and update a finite window — outline

Enlarge the alphabet to include packed m-tuples of original symbols. The simulator’s finite control stores the simulated state, the block currently under each head, its left and right neighbors, and the original head position within the current block. Move right, left, left, right to read the three blocks and return to the current one. Over m original transitions a head cannot pass outside these three blocks. Moreover it cannot visit both neighboring blocks: reaching both from a position within a block of length m would require more than m moves. Thus the finite transition table determines the new state, contents and head position using this finite window. At most the current block and one neighbor require updates; the source uses two transitions for those updates and positioning. Together with the four scanning transitions this gives six. The new finite state records the simulated state and the head’s position inside its resulting block; the neighbor slots may be filled anew during the next scan.
