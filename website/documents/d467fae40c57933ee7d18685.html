The maximum running time of halting machines of a given finite size is well defined but uncomputable. This sharply separates finite mathematical specification from algorithmic accessibility: no general computation can supply the required bounds for all machine sizes.

Review status

Main-run extraction and separate source/standalone review; not formal verification

Statement

For an integer n\ge1, use deterministic Turing machines with n operational states, a separate Halt state, one starting state, a two-way unbounded tape over \{0,1\}, and a transition for each operational state and scanned symbol. Each transition writes a bit, moves one cell left or right, and enters a state (possibly Halt). The machine starts on an all-zero tape. Among machines that halt, \Sigma(n) is the largest number of ones left on the tape, and S(n) the largest number of transitions, including the halting transition. The function S is not Turing-computable.

Proof 1: Doubling, evaluation and erasing — outline

Suppose that S(n) is a computable function and let EvalS denote a Turing machine evaluating S(n). Given a tape with n 1s it will produce S(n) 1s on the tape and then halt. Let Clean denote a Turing machine cleaning the sequence of 1s initially written on the tape. Let Double denote a Turing machine evaluating function n + n. Given a tape with n 1s it will produce 2n 1s on the tape and then halt. Let us create the composition Double | EvalS | Clean and let n0 be the number of states of this machine. Let Create_n0 denote a Turing machine creating n0 1s on an initially blank tape. This machine may be constructed in a trivial manner to have n0 states (the state i writes 1, moves the head right and switches to state i + 1, except the state n0, which halts). Let N denote the sum n0 + n0.

Let BadS denote the composition Create_n0 | Double | EvalS | Clean. Notice that this machine has N states. Starting with an initially blank tape it first creates a sequence of n0 1s and then doubles it, producing a sequence of N 1s. Then EvalS will produce S(N) 1s on tape, and at last it will clear all 1s and then halt. But the phase of cleaning will continue at least S(N) steps, so the time of working of BadS is strictly greater than S(N), which contradicts to the definition of the function S(n).

Proof 2: Reduction from blank-tape halting

The uncomputability of S(n) can also be established by reference to the blank tape halting problem. The blank tape halting problem is the problem of deciding for any Turing machine whether or not it will halt when started on an empty tape. The blank tape halting problem is equivalent to the standard halting problem and so it is also uncomputable. If S(n) was computable, then we could solve the blank tape halting problem simply by running any given Turing machine with n states for S(n) steps; if it has still not halted, it never will. So, since the blank tape halting problem is not computable, it follows that S(n) must likewise be uncomputable.

Level justification

Running an n-state machine for a hypothetical computable S(n) steps gives a halting decider. This direct reduction requires only the definitions of algorithm and blank-tape halting, a small undergraduate discrete-mathematics extension.
